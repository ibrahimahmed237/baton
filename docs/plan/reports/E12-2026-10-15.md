# E12 part 1 — notes audit — 2026-10-15

Part 1 audit is complete; E12 acceptance is not complete. The 24 source rows expand to 95 action/tool cases. This report preserves all 415 current catalogue IDs and all existing wording. It records missing production emitters, missing row-specific pre-action tests and proposed part 2 copy changes. No source, app, fixture, contract or plan-status file was changed. No new behaviour was added, so no regression tests were added.

Initial `git status --short`: only untracked `docs/plan/reports/E9-E10.md`; preserved. Later concurrent edits appeared in the app models, fixture generator/manifest and D10/D11 fixtures; they are owned by other builders and were not edited. No state-changing Git command, worktree, live script, real chat/tool-data read or native app/CLI control was used. All checks use temporary data and fakes.

## Findings to carry into part 2

1. **MISSING production emitter:** `write.any_time` exists but production sync plans get `ReadViews.status.side_notes`, which never selects it for an ordinary ADD. The fixture helper selects it. The OpenCode notes-table row therefore is not proved by the production path. Add its capability-selected pre-action emission and a command test that asserts the count, note ID and unchanged native chats before confirmation.
2. **MISSING explanation:** Q11 requests a note when “Since you left” cannot be trusted. No digest-unavailable catalogue entry exists. `ReadViews.status` suppresses the digest when a counterpart is missing; verified-source failures in `DigestBuilder.for_side` raise `ChatChanged`, potentially refusing the whole status request. A fresh-link requirement is discussed historically but no dedicated explanatory note is emitted. Design safe read projection and catalogue wording together; do not report this as done by the existing generic error.
3. **Fixture-only copy is not production behaviour:** `new_chat.relaunch` is emitted by future fixture providers. `Linker.notes` instead emits `status.new_chat_relaunch` and, where applicable, `create.close_manually`; production link/copy does not execute close/create/reopen. Do not enable the fixture-only three-button closure offer without that lifecycle. `write.app_must_close` occurs in production merge serialization/errors, but link/copy currently refuses a running APP_CLOSED target with the manual-close note.
4. **Missing details in existing wording:** no-reset limit offers omit “It did not say when it resets”; `merge.merged_copy` omits that the link moves; keep/pin receipts omit their delivery/privacy/brief consequences; `keep.too_late` omits destination and delivery time. Old/new proposals below; existing entries were not changed while fixtures are being generated.
5. **User-visible text outside the catalogue remains in argparse description/help and ten command summaries.** App source has the product name “Baton” and formatted numeric/time/percent strings, but no remaining app-authored English action sentence was found in the audited UI sinks. Diagnostics, native data and SQL are separately classified below.
6. **No `baton/services/notes.py` exists.** Notes are spread across service policy methods and serializers. Do not create a facade just for the filename: centralization should preserve existing policy and confirmation fingerprints. E12’s prescribed universal notes_for/status_notes API is not implemented as written.

## Evidence and test meaning

`P` = a production service/command returns the note before mutation; `F` = fixture provider only; `S` = persistent/status or immediate receipt, not a pre-confirmation action. A test that renders a template or asserts a capability is not proof that the note is shown before a write. The app’s exact-display gates are independent evidence: `LinkDialogTests.staleOrIncompleteDisplayCannotApproveChangedNotes` (100), `confirmationUsesOnlyTheDisplayedPreviewAndCopyNeverLinks` (176); `PlanReviewTests.everyStateRequiresItsExactDisplayBeforeAnyMutation` (154), `changedWordingRequiresItsOwnDisplayBeforeConfirmation` (141); `SyncStatusTests.confirmationRequiresTheExactCurrentDisplayReceipt` (88). These tests validate the named fixture/state paths, not every production note-table row. Missing complete row-specific evidence is explicitly marked MISSING.
