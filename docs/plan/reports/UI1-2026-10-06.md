# UI1 — interaction audit, 2026-10-06

UI1 is implemented and independently reviewed, ready to commit after the existing ordered package patches. Engine tests remain **334**; app tests increased from **60 to 68**; Swift build passes. This is a UI repair boundary, not CP2 completion.

## What changed

The review window now allows resizing and advertises full-screen support, and the main content fills larger windows instead of staying at 1000×600. Sidebar, list, dialog choice and popover row padding participates in hit testing; clicking the current sidebar destination preserves its selection.

Long link dialogs and popovers now have bounded, scrollable content. Shared scrolling uses native overlay thumbs with reserved space and no opaque track; mouse-wheel/trackpad scrolling, thumb dragging and native accessibility remain native. The turn strip has room for its horizontal thumb; every valid turn click issues a scroll request, including repeated clicks on the same turn.

## Evidence and limits

Eight new regression tests cover native NSWindow configuration/expansion, repeated section navigation, rendering 1000×600 and 1400×900 in both themes, a single native mouse click in the empty right side of the Suggestions row, long-dialog scrolling to its final actions, repeated turn-jump requests, actual native SwiftUI scroll-host attachment/overflow and isolated scroll probe configuration. The mouse test uses an offscreen fixture window; no real chat or coding app is touched.

Removing the WindowView content shapes causes the exact native click test to fail with the section still Linked. The source was restored in a finally block, then the full checks passed. The tests do not automate a macOS full-screen Space transition.

ImageRenderer does not render native scrollbars. Full-content popover/dialog PNGs deliberately show all content; main-window PNGs are bounded. Shared padding is the same across snapshot/live paths, but the static strip is 27 points versus the live 40-point viewport. PNGs prove content/layout, not actual native scrolling. The 1400-point Graphite window and unavailable-dialog PNGs were visually inspected.

Desktop inspection was attempted with the CUA tool, but fetching the fixture app failed with ScreenCaptureKit code -3811 (“Failed to start stream due to audio/video capture failure”). No capture permission or system setting was changed. The old running fixture bundle was not replaced/relaunched here; the rebuilt executable is app/.build/arm64-apple-macosx/debug/Baton. The visible old instance will retain old behavior until relaunched from the new build.

## Independent challenge

A fresh reviewer was given only UI1's requirements and scoped diff. It found:
1. Horizontal bottom inset did not fit inside the turn-strip viewport — increased live height to 40.
2. Same-turn repeated clicks did not scroll — added a fresh request counter for every valid jump.
3. Snapshot-only tests omitted live insets/interaction coverage — shared padding and added native click/scroll/overflow checks, with a negative click mutation.

Follow-up reviewer: all findings addressed, no remaining actionable blockers, subject to full checks. The full rerun passed. The broader open audit items above are explicitly not claimed fixed.
