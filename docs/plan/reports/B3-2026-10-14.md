## Write safety and format

Every native mutation runs in one SQLite transaction with `BEGIN IMMEDIATE`. The full session row and all its message/part rows are compared with the pre-write snapshot after obtaining the writer lock. A private JSON intent containing exact before/after rows is file-fsynced and directory-fsynced before the first mutation. Rollback applies a row diff; untouched rows and unrelated chats remain untouched. Additional nullable/defaulted columns and BLOB values are retained exactly. Stale receipts refuse changed session, message, part or newly created project rows. A new project is removed only when no other session uses it. Prepared receipts survive JSON serialization and adapter reconstruction, including creation recovery.

Format acceptance uses required tables/columns, with no exact app-version gate. Added mandatory columns without defaults refuse writes. Native IDs follow the measured prefix, 48-bit time/counter and fourteen-character suffix shape; session IDs count down. Writes preserve canonical identities and timestamps through native JSON metadata while generating collision-resistant native IDs. Historical turn timestamps are used where possible; append timestamps advance past the existing rows.

Hooks generate `chat.message` synthetic attachment parts and busy/idle/session-idle notifications using argument-array process calls. Installation is reported separately from readiness: readiness requires both supplied hook-entrypoint availability and explicit plugin-loaded evidence. Installing the file never claims that a restart occurred.

The runner has no default binary. A supplied launcher/binary can be probed, and launch failures/timeouts return the structured `reinstall` finding. Read-only runs deny all tools except read/glob/grep and use root-local XDG data/config/cache/state paths. The desktop uses only the folder deep link and refuses closure while a native reply is unfinished. No password-protected server API is used.

### Built and ordering

- `prepare(add)` and `add` accept an unfinished native reply or explicit busy status, including the check inside the SQLite writer transaction. `create` also works while another chat is replying. Scope, shape checks, duplicate identity checks, compare-before-write, fsynced receipts and SQLite lock handling remain; a locked database raises `ChatHeld`.
- Reader parts belong to their own SQLite `message_id` (the native part's message ID); assistant messages belong to the user identified by `parentID`. Turns are sorted by native user-row `time_created`, then native ID for ties, independent of assistant/part times. An appended Baton turn appears **after the turn being answered**, even when that reply's later parts or continuation assistant rows arrive after Baton's rows. Public timestamps still preserve the copied source history. Orphan assistants are not guessed into a turn. This ordering is documented in `OpenCodeReader.read`.

New tests assert these fields for both add and create and verify that Baton's rows cannot hide an unfinished native reply or make a finished chat look replying.
- After a streaming reply finishes, take-back removes the exact unchanged Baton message/part rows and preserves the native reply's completed rows, parts, usage and native session timestamp. Both prepared-receipt recovery and post-write receipt rollback are covered.
- `cut` determines its retained message set by user boundaries and assistant parents, so late native continuation rows stay with the retained user turn. It remains forbidden while replying.
- **`take_back`, `cut`, `place`, `rename`, and `restore` still raise `ChatReplying` while replying.** App close still refuses too. Existing checks inside the writer transaction remain for operations that change existing rows.
