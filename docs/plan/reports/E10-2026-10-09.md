## Acceptance evidence

- V4/V13/V14 named scenarios cover usage fallback and explicit source/fallback privacy; the private sentinel is absent from paid prompts, summary, transcript, files and copied pins/recent content. Keeping back wins over pinning. The destination-safe path is immutable when a later source-side private artifact is generated.
- M12's native-effect test runs over all 12 ordered fact pairs. It confirms merged canonical order, native artifact content, actual link movement, durable coverage, and preservation of both prior chats.
- Initial source-scoped preview never creates a visible durable link. Linker confirmation stages finish the actual initial/new-target/third-tool relink transition; normal Engine wiring and restart are exercised.
- Preview calls no runner; generation binds disclosed inputs/writer estimates, invokes each eligible candidate at most once in order and persists a new create token/artifact. Creation asks no runner and uses the exact original opening/time. Stored tokens, stage and immutable artifact control behavior even if client fields are forged. Both stages expire after ten minutes.
- Cache is keyed by source/destination/writer and privacy eligibility. Same input uses cached content; eligible append sends prior safe summary plus delta. Changes to old content/privacy/order/chat identity invalidate reuse. An older cached fallback cannot skip a currently eligible destination.
- Summary coverage has its own stored opening fingerprint and original IDs. Only separately emitted originals receive distinct native local IDs and ADDED/SHOWN states. Summary gaps stop synced_up_to. The synthetic opening is not imported as another user turn; disappearing/changed openings refuse rather than falsely claiming coverage.
- Future new activity syncs verbatim in both directions; digest excludes old covered activity and counts actual new turns. Copied originals acquire visibility only from the relevant capabilities/relaunch/reopen evidence; summary coverage never upgrades into shown originals.
- Journal fault injection after prepare, native create, verify and before atomic completion is recovered by a fresh Ledger/BriefService. A post-finalization failure keeps the committed chat/link/receipt. A writer returning a different actual chat is immediately registered for rollback before reading that chat, and neither prepared nor actual create leaves an orphan.
- Brief undo moves the link back while preserving created chats; restore restores the brief identity/coverage. Undo of a delivery whose boundary crosses an active immutable summary refuses before any write or ledger mutation; after undoing that brief, the earlier add can be undone. An add after the summary can be cut or moved into a shorter copy and restored without changing the summary coverage or native opening.

## Challenge and independent findings

Root challenged stage replay, exact candidate selection/cost display, immutable transcript verification, source-scoped third-mode wiring, actual receipt rollback, atomic relink observations, summary gap/visibility, digest and synthetic opening identities. Fixed each in the implementation and actual-effect tests. No assertion that merely sees an intention/step is used as evidence of native creation.

The independent app worker identified a blocking older-add undo: the old generic cut could leave the requested removed content embedded in a summary while recording success. Fixed by refusing an older delivery boundary intersecting active summary coverage before mutation; regression covers both no recent excerpts and recent excerpts, plus permitted future-add undo and brief-then-older-add undo. Public one-line docs were added for new store/ledger/service APIs. Final independent recheck approved both findings; exact reviewer evidence is appended below.

Root mutation evidence showed the immediate successful-generation replay test alone could pass through cache staleness even if token consumption were bypassed. Added a replay after both runners fail into Offline with unchanged input/native chat and no cache, asserting zero retries; retained the failed-validation token replay after restart with repaired original input. The earlier successful replay test is not claimed alone as the proof of durable single use. Root reruns targeted mutations separately.

## Decisions and limits

Uses Ibrahim-approved P1/P2 lifecycle/summary representation and the existing safe undo rule; no new user-facing decision was invented. Later cached fallback is disclosed with a full-input upper bound and validated cache fingerprint, then reused after an earlier candidate fails without another paid call. An immutable summary cannot be surgically edited to remove an earlier delivery, so crossing its boundary fails safely.

These are fake-adapter/temp-file proofs. B2 native safety and both real-app live evidence remain separate and unverified here. C2 serialization/generated fixture reproduction, C3/CP3 production action commands/hooks, and D12 engine-to-window runtime integration remain owed. BriefService is substantial (~620 lines); it uses existing guard/journal/preview/mapping patterns, and module extraction was intentionally deferred to avoid unrelated edits during acceptance repair. No package or CP2 completion is inferred solely from this report's green suites.
