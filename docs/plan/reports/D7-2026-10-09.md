# D7 — coherent hand-off and limit offers

2026-10-09. Builder evidence; root acceptance, independent re-review, common engine/layer checks and commit record are appended below. No commit or live launch was performed by this worker.

Full mode now loads context and limit offers without asking for any brief. Automatic/Offline selection previews the bounded read-only cost or exact offline artifact; the existing separately gated plan review requires consent to generate, then a fresh displayed receipt before creating the immutable result. New optional brief fields preserve older decoding.

Reload clears old conversation, destination, offer, brief and action intent before asynchronous work; stale responses and mismatched identities cannot revive it. Offered Continue and unlinked-dialog destinations come from immutable engine metadata, independent of current selection. Dismissed event identities remain dismissed locally while E9 owns durable once-only offers. Engine recommendations now route to the actual Full/Brief choice.

## Challenges closed

Root found blank generic setup failure and unvalidated destination steps. Both now fail closed with no old actions; a branded dismissible error affordance remains when the engine supplied no sentence. Independent review found missing total/pinned cost and vacuous empty-step acceptance: both HandOff and direct PlanReview now share artifact/stage/policy validation, require a destination create step, verify exact nonnegative candidate costs and bounded total without integer overflow, and require their actual visible engine notes before consent. Offline refuses paid stages; incomplete creation artifacts are not actionable.

Root caught a limit fixture claiming the destination had every turn while its next-message note showed waiting history: those offers now use the behind variant. PNG review found inert recommendation buttons, truncated brief help, false limit explanations in explicit Offline, repeated availability wording and ImageRenderer's unsupported native progress placeholder. Recommendation controls route to the approved choices, text wraps, explicit Offline has its own accurate fixture, availability is rendered once and the loading state uses a native-free SwiftUI progress ring. None adds a new user sentence.

A narrow follow-up allows a named writer's legitimate declared Offline creation fallback, while refusing a different paid writer or undeclared fallback. A dedicated regression covers all three cases.

Two intermediate test-compilation mistakes (await in an assertion operator and nested require macros, then omitted buttons on synthetic test notes) were corrected before the final green check. Production build was green; final build and every app test pass.
