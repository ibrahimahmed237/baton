# E8 — undo and restore, 2026-10-06

E8 is implemented and independently reviewed, ready to commit after UI2. Engine tests increased **334 → 377**; app **71** and Swift build pass. CP2 remains incomplete.

## Built

Undo previews show the exact removed turns, only-here flags and final boundary before mutation. Capability-based execution cuts where safe or creates a shorter chat and moves the link; it preserves the other side and pauses synchronization. An atomic store completion records states, identities, history and committed receipts.

Saved cuts can be restored byte-for-byte under a new reversible write receipt when the chat remains unchanged and the 30-day window has not expired. Startup recovery takes back interrupted writes. Merge undo preserves created chats, returns the link to earlier ones, handles acknowledged attachments at the receiving-message boundary and supplies per-side capability warnings.

## Acceptance and challenge

T7–T11, T10b/c are named scenarios and run for applicable cut/non-cut capability fact sets. U9 exercises all twelve directed pairs and three reachable merge outcomes, split, created-chat preservation, and acknowledgement of attachments. The shared adapter suite checks empty cut/restore, fresh reversible restore receipts and stale-write refusal; native Claude tests use temporary files and verify exact bytes.

The orchestrator challenged release waiting: the implementation now reuses the bounded up-to-ten-second release observation and rechecks before mutation. A possible placement-merge cut issue was examined: E7 cannot emit place and its store rejects that action. E8 does not invent support for unreachable placement merges; ordinary historical place undo follows A9 by listing/saving everything after the insertion boundary.

A separate reviewer found three concrete failures using temporary fake data:
1. A restore preview could be applied after its 30-day deadline — expiry now rechecked before any release/journal/write.
2. Consecutive cuts undercounted what the already-loaded chat still displayed — pending removals accumulate by active chat until later app start/explicit seen evidence; restoration subtracts them.
3. Returning from a shorter chat after new native messages could strand their identities — changed active copies refuse moveback; merge history now saves post-merge observations and similarly refuses stale created-chat moveback.

Further root/reviewer challenge closed two issues:
4. Merge undo omitted the real cut/shorter-copy warning and needs — it reuses ordinary per-side warnings, including release, app-closed, visibility and saved-copy notes.
5. Restore of metadata-only split undo falsely reported success — it now refuses rather than inventing redo-split behavior outside A10.

Acknowledged merge attachments were also checked: undo cuts/copies back before the receiving message and invalidates pending merge approval. Tests cover expiry, active/native drift, unknown format, app-open/held/replying guards, prepare races, delayed/failed release, atomic metadata failure, rollback failure/retry, interruption recovery and exact native restoration.

Final separate reviewer: approved within fixture-only scope, no remaining blockers; 72 focused undo/Claude tests pass. Root full integration gate then passed 377 engine tests plus Swift build and 71 app tests.

## Decisions / limits

Ibrahim explicitly approved resolving U9 by cutting only where supported, creating a shorter copy otherwise, and preserving merge-created chats while moving the link back. Additive writer/store operations and scope corrections implement those existing safety requirements; protected feature specs are unchanged.

C2 still owns rendered Plan/Note JSON and fixture generation. Undo plans provide per-side catalogue ids, exact removes and ends-at data; no sentence is generated in the services. “Earlier copy” is recorded durably in history and catalogue metadata, preserving the original chat bytes instead of renaming it.

C3 needs a route for choosing the side of direction-less history markers. The service accepts an explicit side and verified subsequent delivery boundary; no demonstrable boundary means refusal. Old merge records lacking post-merge observations refuse created-chat undo safely. Undoing a split can reactivate the link, but A10 restore is reserved for cut/copy undo, not split redo.

E8 uses only fakes and temporary native-shaped Claude files. No real coding app/chat, production hook, real adapter lifecycle or command-level undo was exercised. Undo service is 443 lines; further extraction may help maintainability before adding new behavior.
