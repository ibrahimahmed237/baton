# C3 action commands and carry-over fixes — 2026-10-15

## Result

Both assigned carry-overs are fixed. `unlink` and `sync` are registered and tested through first-call preview, dry run, and confirmation. The rest of C3 is **not complete**: the services do not expose all the requested safe actions. No business rules were added to the command layer to conceal these gaps. Commands requiring those missing service contracts were not registered.

The initial tree contained only the unrelated untracked `docs/plan/reports/E9-E10.md`. Other builders subsequently added background/relaunch/brief work and appended output/catalogue entries. Their work was preserved. No state-changing Git command, real chat/tool-data access, live script, or real app/CLI control was performed. App checks used the authorized test script.

## Built

- Relaunch now tracks entry into the write stage. All exceptions in that stage use the same result/reopen path, including when the app started closed. Initial stale validation and pre-close refusal retain their existing exception behavior. A failed closed-app rename returns `applied: false`, its exception name and `relaunch.write_failed`, without opening the app when the plan did not include reopening. The journal restores the earlier content/name.
- Notify catches preparation and application exceptions using the existing failed-delivery branch. The turn-end event remains recorded, the link is queued, its synced claim is removed and `hook.delivery_failed` is returned. A real native change inserted after preparation is covered, as well as injected preparation/application failures.
- Unlink calls `Linker.plan_unlink` and `Linker.apply`. Its notes come from the immutable metadata/record snapshot, including per-side waiting counts. It works on paused links and with missing/unreadable native chats, without reading chat contents.
- Sync refreshes through Applier, previews through Applier, and applies the confirmed service plan. `--to` selects the destination steps while retaining both sides' snapshots and the whole record/conflict flag. Step notes come from the existing status service. Attachment queues a record and never claims native delivery. Conflict is refused by Applier; paused previews contain only service-chosen holds. Pausing after preview invalidates confirmation. Write failures return an unapplied result with an engine catalogue error note.
- Both routes use `ctx.remember` / `ctx.confirmed`, ten-minute C1 storage, and the stored arguments on confirm. Wrong-command confirmation leaves the other command's plan available; stale native/record changes refuse confirmation. Parser dispatch is tested with fakes (the fixture world owns the lock and lifetime, so those are patched only in that test).

## Decisions, proposed contract additions and open questions

1. Kept the assigned ownership boundary. Missing pause safety was treated as a missing **safe service contract**, even though a similarly named service exists. Registering unsafe wrappers would violate the explicit paused-link requirement.
2. Followed C1 confirmation IDs (`ctx.remember`) for the new routes. They need not equal the immutable service fingerprint; the command/arguments/fingerprint association is what is confirmed.
3. Unlink observes metadata and record state, not chat content, following its existing service/architecture contract. This allows removal even when a native chat is missing; stale record/metadata changes still refuse.
4. No frozen contract edits. Resolve the task's all-actions-preview requirement against the contract's immediate pause/resume/keep/send/pin/unpin/open/settings-set behavior before those routes are implemented. If preview/confirm is desired, **propose additive optional preview/confirm forms** and service preview/result types while preserving the documented immediate forms. Existing app immediate dispatch tests should continue to pass. This report does not approve or implement that extension.
5. Sync's existing Plan can add optional service-result diagnostics (`error`, `rollback_error`, `pending_entry`); existing fields are preserved. No new required contract field is proposed.
6. `open` needs a pre-action note/service result even if its final contract remains immediate. `continue` needs a service that owns delivery success and opening order. Settings writes need their own validated service.

## Part 2 — C3b service boundaries and remaining command routes

### Result and scope

Registered all thirteen previously missing action routes: `link`, `copy`, `relink`, `rename`, `continue`, `open`, `settings set`, `pause`, `resume`, `keep`, `send`, `pin`, `unpin`. Their policy lives in services. The recorded orchestrator decision resolves Part 1's immediate-action question: pause/resume/keep/send/pin/unpin are immediate, change only Baton records, return notes and refuse missing targets. Open and settings set retain their immediate contract forms too.

Linker and Names reject paused-link mutations during planning and application, with fresh checks immediately before native creation/rename and before final link replacement. Refusals use the additive `action.paused` note rather than an undo-specific instruction. Existing unlink remains usable while paused. A standalone copy **is allowed** from a paused linked source: A3 explicitly permits copying from any chat without linking. It creates an independent destination and its own copy receipt; it does not remember/update the paused source reference, move its link, change its turns/history, or write either linked chat. Copy-and-link from that source refuses. Tests assert the original link, turns, history and both original native chats stay identical.

`ContinueOpen` selects its opening outcome/note before AppControl, fingerprints that outcome with destination delivery, and opens only after successful native delivery. Conflict, hold, attachment still waiting, failed write, or changed/paused/removed link never opens the destination. Direct opening uses chat selection only when `opens_at_chat` permits it, otherwise opens the folder with the specified instruction naming the chat.

`SettingsWrite` uses SettingsRead's contract defaults/choices/bounds. It parses booleans and numbers, rejects unknown keys, wrong types, non-finite numbers, invalid choices and out-of-bound values before saving. Token thresholds follow the existing positive-whole-token setting rule; glass accepts fractional values from 40 through 95. Save failures carry `settings.error`. No validation rule was added to the command.

Names additionally owns rename lifecycle orchestration. A running app requiring closure is previewed with close/wait/rename/reopen steps and applied through existing E13 Relaunch; replying refuses without closing. A plain rename keeps the existing journaled multi-side path. When lifecycle operations require separate per-app transactions, completed names are retained and a partial-failure note identifies the need to check remaining names.

Link/relink brief mode reuses C6's non-spawning preview and scheduled read-only generation, then a distinct immutable creation confirmation. Poll/cancel forms are available; generated creation tokens remain bound to the originating link/relink command. Neither review stage writes a native chat. Ordinary plans use C1's remembered request/fingerprint checks, including wrong-command refusal without consuming the rightful command's token.
