## Built

Cursor app-store adapter, temporary native-shaped fixtures, and the shared adapter suite. No git state-changing commands, real tool data access, real app/CLI operations, shared-file edits, or fixture regeneration were performed. The initial status contained the unrelated untracked `docs/plan/reports/E9-E10.md`; that file and other builders' changes were left alone.

- Facts match B4: closed-app writes; create/add visible after relaunch; placement supported; cut/release/chat deep links unavailable; context size known; limits have no reset time; hooks need no restart/trust; measured record generation 18; tool activity is not replayed.
- Locator reads `composerHeaders` and app `cursorDiskKV`, never the separate cursor-agent chat store. IDs, names, folders and update times are stable. Archived/script-started headers are excluded from discovery but included in format validation.
- Reader prefers exported transcript text, removes prompt timestamp/query wrappers, uses display IDs/times, retains native tool calls/results, and skips inserted context. Native order also retains Baton-written append/placement bubbles when an export predates them. `turn_ended` is excluded from conversation text; limit failure reasons expose a limit without an invented reset. Display-only chats work without transcripts. File/command evidence and context usage are implemented.
- State checks required tables, columns, `_v`, composer identity, ordered heads and bubble shapes, including hidden chats. Positive integer generations with the same known shape remain writable; unfamiliar generations return the carry-over `new_version` evidence. Missing/malformed versions or required fields block writes. Durable native prompt/stop observations retain busy/open/status/token evidence under Baton's folder.
- Writer prepares and fsyncs a private receipt before changing anything. Create, add, place and rename publish display rows together in one SQLite `BEGIN IMMEDIATE` transaction, comparing the entire target snapshot first. App-running checks also occur inside the transaction and before commit. Existing encoded agent state is preserved; created chats use the measured empty state `~`. Both rename locations change. Cut/restore refuse `NotAvailable`; the existing capability-based undo service consequently creates a shorter chat.
- Take-back compares the saved post-write snapshot, restores original rows including BLOB/text storage and whitespace exactly, works from serialized pre-write receipts after restart, and is idempotent. Transcripts are never written: their original bytes remain exact, and changed transcript bytes block stale rollback. Receipt files are under `.baton/rollback/cursor` by default, or an explicitly injected `rollback_root`; they are not in tool data directories.
- Writes require explicitly allowed existing chat IDs; durable prepared create manifests authorize descendants after restart. Path traversal, symlinked content/config/receipt paths, multiply linked files and SQLite sidecar symlinks are refused.
- Hooks build/install/check/remove just `beforeSubmitPrompt` and `stop`, preserve other entries, and return native `continue`/`additional_context` JSON. No `sessionStart` injection is offered. Readiness remains false when the future C4 entry points are absent.
- Process and runner defaults are inert. Only `on_this_machine` chooses system controls/launcher. App control opens the folder and refuses closing while hook evidence says a turn is busy. The runner checks sign-in and builds a separate `cursor-agent -p --mode ask` request without resuming a linked chat or granting force/auto-approval. Its preview readiness never spawns a command.

## Decisions and contract

- Q14 takes precedence over the older literal version-pin wording: `_v` must be a positive integer, and the required known record shape must match; a different numeric generation alone adds version evidence rather than disabling writes.
- A create uses an explicitly allowed existing composer as the measured header/chat template, clears its agent state and usage, and builds fresh display records. No out-of-scope working chat is used as a create template. Empty scopes refuse production mutation.
- Source message IDs are preserved in display IDs. Foreign tool activity is plain display text with adapter bookkeeping metadata; no native executable tool-call state is written. This preserves the shared-suite round trip while services' mapped `TOOL_TEXT` remains ordinary activity, never a final reply.
- Transcript bytes are read-only evidence, rather than a second publication destination. A transcript changed since preparation/publication causes `ChatChanged`, preventing rollback from overwriting newer app data.
- No new command, contract field, catalogue wording or frozen-contract change is needed for B4. Proposed contract additions: **none**.
