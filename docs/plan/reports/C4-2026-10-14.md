## Built

- Registered `catch-up --tool T [--chat ID] [--turn-id ID]` and `notify --tool T [--chat ID] [--turn-id ID] [--event turn_end|busy|idle]`. Native stdin can supply chat and turn identities. Missing event defaults to `turn_end`, retaining existing adapter command compatibility.
- Small `HookCall` boundary with separate Claude (`session_id`, `prompt_id`), Codex (`session_id`, `turn_id`), Cursor (`conversation_id`, `generation_id`) and OpenCode (`sessionID`, message ID, busy/idle event) parsers. Commands contain no per-tool rules.
- Catch-up calls the existing Applier refresh and preview, attaches only a non-decision `attach` step, uses DigestBuilder with the digest first inside the existing catch-up marker, includes each turn's timestamp, and records attachment through `Applier.record_attached`. It never writes the native chat. Public tool activity is flattened through the existing mapping service; private reasoning is excluded.
- Notices obey `notice_on_attach`; notice sentences, command labels and the timestamp/body template are catalogue entries using specification wording.
- Durable turn-ID idempotency checks the existing attached-event message identity. Already attached turns are not reattached, and newly arriving history is also refused on a repeated invocation of that same turn.
- Notify records the event in the existing store, refreshes and previews, and applies only planned `add` steps without extra requirements or decisions. Fresh held/open or replying conditions and the most recent durable busy event refuse writes. Hooks never close or release an app/chat. Other turns remain waiting for later delivery.
- Native output is delegated to each adapter's HookSupport: Claude/Codex prompt JSON; Cursor `continue` and `additional_context`; OpenCode plain synthetic-part text. Empty/error replies use native-safe output: Claude/OpenCode empty, Codex `{}`, Cursor prompt `{"continue": true}` and stop `{}`. Codex Stop prints exactly `{}` with no newline.
- Installed Python prompt/turn-end entry points wrap stdin reading, engine construction, lock acquisition and service work in a default two-second SIGALRM deadline. Timeouts bypass ordinary service exception/rollback loops; unfinished journaled writes recover under the next command lock. The hook closes its store directly rather than reacquiring an unbounded cleanup lock after its deadline. Failures log and return native empty output with exit 0.
- Added a corrected OpenCode plugin asset carrying prompt message IDs and busy/idle event arguments, using execFile without a shell and bounded execution.
- Added an early CLI dispatch helper, ready to be connected before ordinary CLI engine construction/locking. See the required integration below.

## Decisions where the plan was silent

- The hard deadline uses a main-thread process timer on this Mac, rather than a background thread that could continue writing after the hook returned. Embedded non-main-thread calls fail closed. The existing signal handler/timer is restored.
- Native safe empty output takes precedence over the task's generic “prints nothing”: Codex must receive `{}`, and Cursor beforeSubmitPrompt receives `continue: true`.
- For CLI callers lacking a turn ID, use the last native prompt ID (or a stable `first-message` identity for an empty chat) as a conservative deduplication fallback. This may delay later attachment if a tool fails to supply fresh identity; the corrected OpenCode plugin passes the exact message ID.
- Automatic notify does not perform `add_after_release`, close/create/relaunch steps, or a step with extra `needs`. This avoids consented actions or app lifecycle changes from a hook. A later explicit sync can do them.
- Notification busy evidence is a refusal in addition to fresh native conditions; idle/turn_end do not override a native replying/held refusal. No claim that a hook proves reopening or visibility is introduced.
- On an attachment emission/process crash after the store's delivery record commits, the text may not reach the caller. Hook protocols have no acknowledgement transaction with stdout; exact turn-ID retries therefore favor avoiding duplication. This is not claimed as crash-proof delivery acknowledgement.
