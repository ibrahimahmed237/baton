## What was built

`baton` runs as `python3 -m baton.cli.main` and, once installed, as the `baton` command (`pyproject.toml` entry point `baton.cli.main:main`; not installed here, no pip). A command is parsed, one command function runs on an `Engine`, one JSON object is printed. `baton links --json` prints `{"links": []}` on an empty home.

- `wiring.build(root=None, *, clock, adapters, adapter_roots, tools_home, environ, entries) -> Engine`. Creates the folder, the SQLite store (`baton.sqlite`), the adapters, the plan book. Services (`applier`, `linker`, `merger`, `undo`) are built on first use, because building one runs the recovery of unfinished writes and a read command must not do that.
- Adapter registry: `baton/cli/tools.py`, a tuple of `ToolEntry(id, label, module, adapter class, home)`. Claude, Codex, OpenCode, Cursor are listed. `wiring.load_adapters` imports each; a tool whose module is missing, does not import, does not construct or reports another name is left out and the reason is kept in `engine.unavailable` (it never fails a command). Claude is wired now. Codex lights up by itself when `baton/adapters/codex/tool.py` defines `CodexAdapter(root)` with `name == "codex"`.
- Roots: store folder = argument, else `BATON_HOME`, else `~/Library/Application Support/Baton`. Tools home (what adapters get as root): `adapter_roots[tool]`, else `tools_home` argument, else `BATON_TOOLS_HOME`, else `<store folder>/tools` when the store folder was chosen explicitly (argument or `BATON_HOME`), else the real home. So a test or a trial run can never read real chats by accident.
- `output.py`: `note`, `note_list`, `chat`, `chat_from_ref`, `side_condition`, `message`, `turn`, `side_usage`, `since_you_left`, `next_message`, `side`, `step`, `plan` (extra fields for removes/ends_at/brief/replying), and errors: `error(BatonError)`, `internal_error`, `usage_error`. `tool_label` is emitted in Chat, Side and Step with `Claude`, `Codex`, `OpenCode`, `Cursor`. Note values named `tool`, or ending `_tool`, are replaced by the label before rendering and in `values` (matches app/Fixtures). Notes whose id starts `mapping.` are exempt (a tool call's name is not a coding app).
- Global flags `--json` (accepted, always JSON), `--dry-run`, `--confirm PLAN_ID`; accepted before or after the command; `--dry-run`/`--confirm` only on commands registered with `plan=True` and mutually exclusive.
- Plan ids: `cli/plans.py`. `PlanStore` protocol (`save/load/delete/all`) with `MemoryPlanStore` and `FilePlanStore` (one JSON file per plan in `<root>/plans/`, atomic write, ids must match `p_[A-Za-z0-9_-]+` so no path tricks). `PlanBook(store, clock)` keeps a plan 10 minutes (exactly 10 is expired, by the injected clock).
- Commands: `baton/cli/commands/__init__.py` has `Command`, `CommandRegistry`, the decorator `command(name, summary, arguments=..., plan=False)`, `Context`, and `discover()`, which imports every module in the folder. A name with a space (`setup install`) is a sub-command next to a command of the parent name.
- `baton/cli/commands/links.py`: the one real command. Refreshes with ChatRefresh without constructing recovery services; headline selection belongs to services.status.link_headline.

## How confirming works (C3 needs this)

(Updated in review round 1; see below.) The next `--confirm` runs in a new process, and the services' plan objects cannot be stored, so the stored plan is the request: command name and its arguments, with the service's plan id kept as its `fingerprint`. The id shown to the app is a new confirmation id per preview. A plan command does:

```python
def plan_again(arguments):  # plans the same request from the chats now, returns the service's plan id
    planned["plan"] = ctx.engine.linker.plan_link(arguments["from_side"], arguments["chat"], arguments["to"])
    return planned["plan"].plan_id

if ctx.confirm:
    ctx.confirmed(plan_again)     # claims the plan (used up), ChatChanged unless the fingerprint matches
    result = ctx.engine.linker.apply(planned["plan"], planned["plan"].plan_id)
    return output.plan(ctx.confirm, ..., applied=result.applied)
plan = <service plan>
shown = ctx.remember(plan.plan_id, {"from_side": ..., ...})   # also for --dry-run; returns the confirmation id
return output.plan(shown, ...)                                # applied false
```
Arguments must be JSON-able.

## Decisions where the plan was silent

1. Unknown, expired, other-command, already-used and stale plan ids all raise `ChatChanged` (kind `chat_changed`, note `write.chat_changed`). No new error kinds.
2. A plan is used up the moment it is claimed, whatever happens next.
3. Usage errors (bad command line) print `{"error": {"kind": "usage", "message": ...}}` and exit 2. Crashes print kind `internal` with the plain `error.unexpected` note, exit 1, and the details are logged to stderr.
4. A command may return a `str`; it is printed as is (for `catch-up`, C4).
5. `Chat.link_id` is always emitted (null when unlinked). `Side.condition` carries all seven fields (4 documented + the 3 CP1 additions). `Chat.updated_at` and `Turn.started_at` are empty strings when unknown (the Swift models need strings); `Turn.ended_at` is null when empty. `Turn.messages` only when asked; a message has `tool` only when it has one (as in the fixtures).
6. `Turn.tokens` = `LedgerTurn.size // 4`, the same estimate as `services.status` (`_CHARS_PER_TOKEN`); the constant is duplicated in `output.py` rather than importing a private name.
7. `side_usage.percent` is rounded to one decimal; `limit` is `{"resets_at": ...}` when the limit was hit, else null.
8. An error whose note needs a value the error does not carry is still printed (missing values rendered empty) instead of crashing; an error with no catalogue note (`SetupIncomplete`, `setup.<finding>`) gets the `error.unexpected` note (see review round 1).
9. The 3 services Merger/Undo/Applier each build their own Applier, so each construction runs journal recovery once; Engine builds them lazily.

## Review round 1

Test counts: 640 in the suite now; every test of mine passes (`tests.unit.test_cli` 62, `tests.contract.test_shapes` 45). One failure is not mine: `tests/unit/test_notes.py::test_fixture_receipts_stop_before_first_waiting_turn` on the new fixture `app/Fixtures/status.d7_brief_fallback.json` (another agent's unfinished work; not touched). I checked that the new tests fail when each fix is reverted (claim, symlink and id checks, expiry re-check, folder mode, links refresh, discovery guard, tools-home guard).

1. **Two processes can confirm the same plan.** `PlanStore` has a new `claim(plan_id)`; `FilePlanStore` claims by `rename` of the plan file to a unique name (only one rename can succeed) and then reads and removes it. `PlanBook.confirm` claims first and only then plans again and applies. `Context.done()` and `PlanBook.forget/recall` are gone; the claim is the use. Tests: 8 threads racing 20 times, exactly one wins; a second confirmation is refused and plans only once.
2. **Loader trusted the embedded id.** Files are validated: exactly the five fields, embedded `plan_id` equal to the requested id, text fields are strings, `arguments` an object. Anything else (also undecodable bytes, empty, a JSON list) reads as "not kept", which is a `ChatChanged` refusal, never an internal error. Tests cover each broken shape, and a damaged file through the command line.
3. **Symlinks.** The plans folder is created with mode 0700 and opened with `O_NOFOLLOW | O_DIRECTORY`; it must be ours, and a looser mode is set back to 0700. All file operations go through that directory descriptor (`dir_fd`). Plan files are opened with `O_NOFOLLOW`; writes use a temporary file created with `O_EXCL | O_NOFOLLOW` (mode 0600) and an atomic `rename`, which replaces a link rather than writing through it. A symlinked folder: `save` raises `OSError`, `load`/`claim`/`all` find nothing and nothing is written to the target. Tests for all of these.
4. **Fingerprint used as the public id.** Every preview now gets its own random confirmation id (`p_` + 32 hex); the service's plan id is stored as `fingerprint` and compared at confirm. `Context.remember(fingerprint, arguments)` now returns the id to show. Tests: same state previewed twice gives two ids, neither equals the fingerprint; a later preview cannot overwrite or revive an earlier one.
5. **Stale plan stays after ChatChanged.** The plan is already claimed, so it is gone whatever planning does (stale, ChatChanged, crash). Test over all four outcomes.
6. **Expiry only before replanning.** Checked when claimed and again after planning, immediately before apply. Test with a clock that moves during planning.
7. **Empty times.** The Swift models (`app/Sources/BatonKit/Models/Shared.swift`) have `Chat.updatedAt: String`, `Turn.startedAt: String`, `Turn.endedAt: String?`. So `updated_at` and `started_at` are now `""` when unknown (also for the missing-chat path in `links`), `ended_at` stays null when empty. Tests assert the types. Open question for the contract: it says nothing about unknown times; an empty string is the only value both the document and the Swift models accept for `updated_at`.
8. **`links` status policy (superseded by resume review).** The original Applier-based refresh could recover another live write. Final implementation uses ChatRefresh directly and services.status.link_headline. Listing can reconcile ledger observations, but never constructs recovery/writer services. Missing chats are never marked in sync. Pending-journal preservation is covered by a regression.
9. **"Carried out" tests did not apply anything.** The probe command now calls `Linker.apply` on the confirmed plan. Tests assert the created Codex-like chat's contents (prompts and replies; Codex does not replay tool calls, so tool activity is not compared), the stored link, and that nothing exists before `--confirm`.
10. **Inherited `BATON_TOOLS_HOME`.** `wiring.build` ignores `BATON_TOOLS_HOME` when `root` is passed in code (as it already did for `BATON_HOME`). The test base class now clears both variables, and guard tests prove an inherited `BATON_TOOLS_HOME` does not move the adapters of a `build(root)`, while it still works for a `BATON_HOME` trial run.
11. **Exception prose in errors.** Additive catalogue note `error.unexpected` (tone `danger`, "Something unexpected went wrong in Baton. Check your chats before you try again. Baton's log has the details."). It is the note of an `internal` error, and of a refusal whose exception has no catalogue note (`SetupIncomplete`, base `BatonError`). I did not claim "nothing was changed", because a crash during apply may have changed things. The technical message is no longer printed; it is logged (`logger.exception` for crashes, a warning for the refusal). `app` reads only `kind` and `note` (`EngineCommandError`), so no detail field was kept. `usage` errors still carry their `message` (argparse text for the caller, never shown). **Shared file edit:** one line added after `merge.split` in `baton/notes/catalogue.py`.
12. **Discovery outside the crash handler.** `discover()` and parser building are now inside the guarded block; an import failure prints the contract error object and exits 1. Tests: a command module that fails to import, and an argument definition that raises.

## Final resume review — 2026-10-09

**Accepted C1; 119 focused tests and 650 total engine tests pass; app builds and passes 115 tests.** Initial resume baseline was 640 engine tests with one false D7 receipt; that fixture is corrected but D7 remains unaccepted for separate routing/catalogue findings.

Independent review found and root fixed:

1. Read `links` constructed Applier and recovered an in-progress native write. It now uses ChatRefresh directly. A begun entry and fake native write survive listing; no writer take_back is invoked.
2. Pending did not imply crashed. Per-root OS file lock covers ledger initialization and CLI dispatch, including service construction/recovery through planning/applying. Another process cannot enter while a command runs; it can after exit or exception. Locks are released by the OS on process death. The lock file is owned, regular, singly linked and private.
3. Existing 0755 roots and 0644 SQLite files stayed public. Owned no-follow storage is now secured to 0700/0600 before Ledger opens. Symlink roots/databases/locks, hardlinked database files and mismatched ownership are refused. Tests use temporary files only.
4. Ordinary adapter construction failures escaped. They now populate unavailable; KeyboardInterrupt still escapes. One broken tool cannot take out the healthy tool.
5. Headline policy was in CLI. It now resides in the status service, with the CLI doing serialization/rendering.

Final separate reviewer found no remaining C1 code blocker. Its documentation warnings are resolved here, in Engine's docstring, ARCHITECTURE.md and the C1 track.

Direct callers must use:

```python
engine = build(root)
try:
    with engine.command_lock():
        plan = engine.linker.plan_link(source, chat, target)
        result = engine.linker.apply(plan, plan.plan_id)
finally:
    engine.close()
```

Do not nest command locks. main already takes it. C4 must account for lock contention within its two-second hook deadline; the skeleton's interactive command lock currently waits indefinitely.

Root challenge injected three in-memory regressions (no disk mutations): bypassing CLI lock, leaving storage permissions loose, and restoring recovery on read. All three new safety tests fail for their intended reason; restoring the implementation passes the full suite. Full outputs, independent findings and CP2 limitations are in the resume report.

No installed entry-point or live tool run is claimed; C1's documented empty-home proof runs via python module/subprocess on isolated BATON_HOME. C2 read commands and C3 production action commands remain separate packages.
