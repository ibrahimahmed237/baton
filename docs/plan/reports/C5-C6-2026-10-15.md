# Task R — C5 and C6, 2026-10-15

C5 is implemented against E13, with fake-only verification. C6 background generation, review, brief creation and closed-chat second-opinion addition are implemented. **C6 is not fully complete:** adding a reviewed answer to an open chat through the prompt-hook queue requires integration outside this builder's assigned files. That case safely refuses instead of claiming attachment.

## What was built

- `relaunch --tool T [--when-idle] [--then-sync L]`: preview names the exact chats written, turn IDs and close/wait/reopen operations. Replying chats are named; unknown reply state (`None`) produces a named refusal. Confirmation stores the exact E13 plan, including its original expiry. A detached worker applies it under the command lock. `--status ID` polls the durable request; `--cancel ID` cancels a pending request. Idle retries are bounded by E13's expiry. Changed records/chats still refuse.
- `brief --link L [--to T] [--writer auto|T|offline]`: non-spawning preview, disclosed candidate token estimates and their bounded total, explicit writer-order/selection notes, background generation after confirmation, then a distinct immutable creation preview. Only confirmation of the creation token writes a chat. Existing E10 privacy, pins, recent turns, cache and transcript verification remain authoritative.
- `ask --chat T:ID --question Q [--tool T] [--turn N] [--add-to-chat]`: preview names the other agent, explains read-only access and estimates request tokens. Confirmation queues a separate read-only runner session; polling displays the stored answer. `ask add --answer A`, or `ask --answer A --add-to-chat`, produces a separate add preview and token. Confirmed closed-chat addition journals, verifies and labels the second opinion, then records the native turn for ordinary future sync. Linked and unlinked source chats are supported. Kept-back/skipped turns are excluded before the prompt is composed; selecting such a turn refuses.
- `brief` and `ask` accept `--status ID` and `--cancel ID`. Jobs have one shared 120-second runner deadline, including brief fallback attempts. Late/cancelled results cannot become reviewed results. The runner is always called with `read_only=True`. A runner's optional `cancel()` is invoked on an active stop. Results are stored through existing RecordStore artifact/cache methods, not a new database or adapter dependency.
- Background workers rebuild their engine after releasing inherited descriptors. Service work holds a fresh command lock; the worker releases it while the read-only runner executes, allowing polling and cancellation. Tests inject a scheduler; one test verifies actual detachment using only fake adapters and a temporary root.

## Decisions where the plan was silent

- The additive no-`--to` brief signature defaults to the last side returned by the stored link. `--to` remains available to select the destination explicitly. - Closed-chat additions commit the native journal receipt before ordinary turn recording. If recording subsequently fails, the native write remains committed and the next normal refresh can record it; it is never rolled back after commit.

### What was fixed

1. **Linked opinion privacy:** a linked request can select only its linked counterpart. An installed third adapter cannot receive a prompt without the counterpart's exclusion policy. A three-adapter regression checks refusal before any runner call.
2. **Relaunch cancellation boundary:** the service worker rechecks durable pending state after obtaining the command lock, before any relaunch action. The test cancels on lock acquisition and verifies no close, write, or open call.
3. **Runner supervision:** daemon threads were replaced by an injectable process controller. The default controller runs the runner in a child with its own process group, polls its answer/error pipe, terminates the group and reaps the child on every exit path. The startup handshake is polled within the same deadline. Missing runner cancellation handles no longer exempt runners from supervision. Injected controllers verify termination/reaping on deadlines, active cancellation, errors and success; a mocked process controller verifies TERM/KILL and joins. No real runner is exercised.
4. **Relaunch expiry:** the original plan expiry is persisted as the pending job deadline. Polling alone produces an unapplied `idle_timeout` result after expiry, including when the worker never starts. The original one-hour retention remains separate.
5. **Retention cleanup:** the store port now exposes cleanup and explicit, connection-scoped resource ownership. Generation approvals, newly generated creation approvals, immutable artifacts, cache entries, job requests, duplicate result artifacts and job cache rows are deleted when their owning jobs expire. Ownership is written alongside each resource, so a crash does not depend on a worker's finalizer to register it. Multiple background owners protect shared caches until their last owner expires; existing external caches and records created on another connection are untouched. Canonical artifacts referenced by coverage or history remain available for sync/undo/restore. Tests close and reopen SQLite and verify actual brief-job cleanup, with and without confirmed native creation.
6. **Reviewed-answer queue:** separately confirmed open-chat addition persists an addressed, expiring answer in SQLite. The prompt hook consumes it through the adapter attachment port and records a durable one-time receipt. Before confirmation nothing is attached; queuing makes no native write. Restart, wrong destination, duplicate prompt, missing native prompt identity, unlinked chats, expiry, pause and changed exclusion policy are covered. Add previews say `attach`, and the receipt says queued rather than claiming native addition. The usual closed-chat journalled addition remains available.
7. **Frozen responses:** `ask --from T:ID --turn N --tool T --question Q` returns immediate `answer_id`, `answer`, `tokens`, `seconds`, and `notes`, with only additive job/routing fields. Default brief generation confirmation returns the distinct immutable creation Plan immediately. Its creation confirmation preserves the Plan's steps and brief details. Explicit `--background` retains queued/pollable generation; the new `--chat` opinion signature retains its staged review. Contract tests cover both immediate and asynchronous forms. CONTRACT.md was not changed.
8. **Thin commands:** new service modules own relaunch restoration, reply-state checks, approval, idle retry, lock-boundary cancellation, brief destination selection, readiness wrappers, runner replacement, bounded generation, leases and opinion job entry points. Commands parse, dispatch, register confirmation tokens and serialize service results. No CLI call to private relaunch validation or CLI runner replacement remains. Existing behavior tests and an architecture regression cover this boundary.
9. **Restart assertion:** the durability test closes the original connection and constructs a new Ledger on the temporary database before retrieving its answer.

### What was built

1. **Opinion privacy:** prompt eligibility is the intersection of the source chat's and writer chat's allowed turns. Either side's kept-back/skipped state excludes the whole turn before composing context/recent exchanges. Explicit selection of an excluded turn refuses. 2. **Runner cleanup:** group signal failures (including PermissionError) fall back to direct child termination/kill. Direct signal failures are handled too. Nested finalizers attempt both joins and close the pipe even if signaling or joining fails. Mock-only regressions verify permission failures do not bypass termination, reaping attempts, or descriptor cleanup.
3. **External retention:** job ownership now includes the separate CLI creation-review token and the transcript path/digest. Transcript registration occurs inside the existing artifact transaction. SQLite cleanup deletes owned artifacts/plans/caches before considering their transcripts; any surviving artifact reference protects its snapshot, including canonical coverage/history artifacts. Injected cleanup handlers delete CLI reviews and verified snapshots under Baton's private transcript directory. Filesystem alias paths are accepted; a symlinked/non-owned transcript directory is refused. When a connection has no external cleanup handlers, durable ownership rows remain for a later retry instead of being discarded. Commands install handlers again after reconstruction/restart. Restart tests using real temporary FilePlanStore/FolderTranscripts verify actual review-file and snapshot removal, and preserve the snapshot after canonical creation.
4. **Test process safety:** both background test classes activate tests/fixtures/no_processes.py and an additional setsid guard. The former real detached-worker test injects the scheduler and verifies pending/completed persisted results. A guard regression rejects uninjected fork, setsid, Popen and run. Detachment itself is checked separately with mocked fork/session/descriptor/exit operations; tests exercise parent return and child success/failure cleanup without creating a process.
5. **Worker boundary:** background_worker.py owns detachment, session creation, inherited descriptor disposal, engine reconstruction through an injected factory, dispatch through an injected scheduler, and fresh-engine closure. The CLI helper only supplies wiring's build callable and the work callback, retaining compatibility with other builders' callers. An AST regression rejects fork/session/descriptor/reconstruction policy in brief, ask and relaunch command modules.
