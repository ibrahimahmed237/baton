## What was built

**E11.** `Marks` exposes keep, send after all, pin, unpin, pinned-turn filtering, pause and resume over `RecordStore`. It returns the fresh turn or link and supplies W13 missing-turn notes through `status_notes(link_id, side)`. Keeping an already-delivered turn preserves the store's refusal with its destination and delivery time. Tests exercise real planner/applier and brief services: later turns still arrive, attachment is blocked while paused, resume observes conflicts, pins remain full originals in a brief and keeping back wins over a pin.

`Names.names()` reads both native names afresh and remembers their references without renaming. `plan_rename()` selects sides explicitly, skips already-matching names, records each side's closure/visibility needs and fingerprints both chats and the record. `Names.apply()` prechecks all selected sides, journals and verifies each rename, commits its exact earlier title and receipt atomically, and returns a `RenameResult`. Stale previews and changes during a preceding side's write refuse; attempted renames are rolled back in reverse order on failure. `Names.notes()` provides the per-tool explanation. Existing `ChatRefresh` already reads names on every refresh and was not edited.

**E13.** `SetupCheck` requires an independent injected installation probe. A missing tool is left alone: no format, hook or runner probe is called. Installed tools report facts, version/shape trust, hook installation/approval findings, and background availability/sign-in findings, preserving adapter-supplied remedy notes. Failed format/hook probes do not hide other checks. A known shape with a new release remains usable with the existing informational note.

`Relaunch.plan_relaunch()` produces close → wait until still → approved writes → reopen. It inventories all chats, including unlinked ones, names every reply in progress and offers the idle variant. `apply()` refuses while any chat is replying. An idle plan returns `waiting=True` until a later call observes every chat idle. The caller owns scheduling; the service retains no queue or background thread.

Graceful closure uses `AppControl.close()`, then waits for the app to stop, all chats to be released and two consecutive identical reads. The total settle deadline is one minute. Timeout or closure failure writes nothing. Fresh record, contents, names, setup conditions and capability checks protect both planning and execution. Closure/idle transitions are permitted explicitly; changed content requires a new preview. Writes use the existing journaled applier or the new names service. Reopen selects the chat when supported, otherwise its folder. A reopen failure preserves and reports successful writes.

`--then-sync` service input selects one link. App-wide relaunch plans every unpaused link for that tool and uses one close/reopen cycle; a conflict refuses the whole preview. Per-link write failures retain verified earlier writes and explicitly report `completed_links` plus a partial-completion note. Closed-app sync needs no close/reopen, implementing Q13; an explicitly requested relaunch can still open a closed app after its writes. Confirmed rename plans can be executed inside the same safe lifecycle.

## Decisions and proposed contract additions

- Installation evidence is mandatory injection, rather than assuming an implemented adapter means an installed tool. `ready` describes sync prerequisites; additive `background_ready` describes the runner independently, so a missing background runner does not disable ordinary sync or the offline brief.
- Rename needs use the existing capability sets: `CLOSED_OR_RELEASED`/`APP_CLOSED` require closed-app rename; `NOT_HELD` shows names after relaunch; `ANY_TIME` shows names at once. No tool name branch or capability/fixture shape change was added. Native writers retain their own stricter guards.
- Idle waiting is a stateless retry result for C5/C6 scheduling. Reply/closure condition transitions are allowed, but completed replies that change the confirmed content invalidate the preview (`ChatChanged`). This preserves the frozen confirmation rule; automatic reapproval of changed content is not implemented.
- The task's explicit refusal while replying takes precedence over the older spec's “Close anyway” offer. The new service notes offer idle/cancel only and preserve old catalogue entries for existing fixtures.
- App-wide relaunch respects pause and ordinary conflict decisions. Writes remain atomic per link, as the existing applier supports; completed links are disclosed if another link fails.

Propose additive CONTRACT entries for step actions `rename` and `wait_until_still`, setup `background_ready`, and relaunch receipt fields `waiting` and `completed_links`. Existing `close`/`reopen` actions, command signatures and all frozen fields retain their meanings. No frozen document was edited.
